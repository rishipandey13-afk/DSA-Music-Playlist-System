1. ABSTRACT

Audio streaming applications like Spotify, Apple Music, and YouTube Music require dynamic playlist management where tracks can be added, removed, reordered, and traversed in both directions without computational lag. Classical static arrays fail in such environments because insertions and deletions require costly O(N) memory shifts, and dynamic array resizing incurs heavy reallocation overheads.

This mini project presents the design and implementation of a Music Playlist Management System using modern C++ (C++17). The system is built upon two core classical data structures:

  1. Doubly Linked List (DLL): Serves as the primary playlist container, where each track node contains pointers to both the next and previous tracks. This provides constant-time O(1) forward and backward playback navigation, seamless arbitrary insertions, and in-place list reversal without allocating auxiliary arrays.
  2. Stack (LIFO): Employs a custom dynamically allocated linked stack to automatically maintain a chronological history of recently played tracks, mimicking real-world media history features.

The application provides an interactive terminal interface equipped with robust input validation, preloaded demonstration songs, and complete administrative control over track attributes.

2. PROBLEM STATEMENT & OBJECTIVES

2.1 Problem Statement

In multimedia software engineering, a playlist is continuously modified at runtime. Users expect instantaneous response times when clicking "Next Song" or "Previous Song", inserting a track "Play Next", or undoing a play action. A linear singly linked list allows forward navigation but requires an expensive O(N) re-traversal to reach the previous node. A doubly linked list resolves this fundamental drawback.

2.2 Project Objectives

  • Implement a fully functional Doubly Linked List node architecture containing unique Track ID, Title, Artist, and Duration.
  • Enable bidirectional traversal (Next Song and Previous Song) with circular boundary wrap-around.
  • Support dynamic insertion at the head, tail, and arbitrary user-specified positions.
  • Support deletion by Track ID with automatic link restoration and memory reclamation.
  • Integrate a Stack data structure to track playback history in Last-In-First-Out (LIFO) order.
  • Implement an in-place pointer reversal algorithm without additional list copies.
  • Provide linear search capabilities by track title or artist keyword.

4. DETAILED ALGORITHMS

4.1 Insertion at End of Playlist (O(1))

Algorithm AddSongEnd(title, artist, duration):
1. Allocate memory for new Song node: newSong.
2. Initialize newSong.id = nextId++, newSong.title = title, newSong.artist = artist, newSong.duration = duration.
3. Set newSong.next = nullptr, newSong.prev = nullptr.
4. If head == nullptr (playlist empty):
     head = tail = currentSong = newSong
5. Else:
     tail.next = newSong
     newSong.prev = tail
     tail = newSong
6. Increment totalCount by 1.

4.2 In-Place Playlist Reversal (O(N) Time, O(1) Space)

Algorithm ReversePlaylist():
1. If head == nullptr or head.next == nullptr, return.
2. Set curr = head, temp = nullptr.
3. While curr != nullptr:
     temp = curr.prev
     curr.prev = curr.next
     curr.next = temp
     curr = curr.prev  // Moves to the next node in original sequence
4. If temp != nullptr:
     tail = head
     head = temp.prev
